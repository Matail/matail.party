# Matail

한 명이 만드는 작은 게임 스튜디오 사이트. Astro 6 정적 사이트 + Decap CMS.
디자인 콘셉트는 **심야 작업실** — 거의 검정에 가까운 배경에 전등 하나의 따뜻한 앰버 빛.

## 인트로 (2D 픽셀아트)

첫 방문에 한 번 재생됩니다 (약 9초).

1. 암전 → 천장 전구가 깜빡이며 켜짐
2. 캐릭터가 화면 밖에서 걸어 들어옴 (8프레임 워크 사이클)
3. 가운데 서서 정면을 봄
4. 들고 있던 노트북을 엶 → 화면에 로딩 막대가 차오름
5. 카메라가 화면 속으로 들어가고, 로딩이 끝난 화면이 그대로 이 사이트가 됨

**전환이 이어지는 원리**: 노트북 화면 안은 캔버스 그림이 아니라 **진짜 DOM**입니다.
`Header`, `Hero` 컴포넌트를 사이트와 똑같이 렌더해서 노트북 화면 자리에 축소해 놓고,
카메라가 줌인하는 만큼 그 DOM을 확대합니다. 화면이 뷰포트를 가득 채우는 순간
스케일이 정확히 1이 되므로, 진짜 페이지로 바뀌어도 한 픽셀도 움직이지 않습니다.
(그래서 히어로가 `src/components/Hero.astro`로 분리돼 있습니다 — 두 곳에서 같이 씁니다.)

규칙:

- 세션당 1회 (`sessionStorage`의 `intro-played`)
- `prefers-reduced-motion`이면 재생하지 않음
- 스프라이트 로드 실패 / 9초 초과 시 건너뜀
- ESC 또는 우측 하단 버튼으로 건너뛰기
- 다시 보려면 `/?intro=1` (푸터 링크) 또는 `/#intro`

연출 튜닝: `/?intro=1&t=5.2` 로 열면 그 시점에서 **정지**합니다.
그 상태에서 콘솔에 `__setT(6.4)` 를 치면 다른 시점으로 옮겨 가며 한 프레임씩 볼 수 있고,
`__intro.state` 로 그 순간의 모든 값을 읽을 수 있습니다.
타이밍은 `src/scripts/intro2d/index.js`의 `T` 상수 하나로 조절됩니다.

캐릭터 스프라이트는 PixelLab에서 만들었습니다 (256x256).
서 있는 8방향 + 걷기 8프레임에 더해, **두 구간은 "앞뒤 포즈를 양끝으로 잡고 사이를 채운"**
PixelLab v3 보간 애니메이션입니다 — 끝 그림이 이웃 포즈와 정확히 같아 이어붙일 때 튀지 않습니다.

| 파일 | 내용 | 만든 방법 |
|---|---|---|
| `turn-0~8.png` | 옆 → 정면 회전 9프레임 | east 로테이션 → south 로테이션 보간 |
| `raise-0~11.png` | 팔을 가슴까지 드는 12프레임 | south → hold.png 보간 7장 + 손이 크게 뛰던 두 구간을 다시 보간해 채운 5장 |
| `open-0~8.png` | 뚜껑을 여는 9프레임 | **AI 보간을 쓰지 않고** `hold.png` 한 장에서 직접 조립 (아래) |

`turn-0` 은 `east.png`, `turn-8` 과 `south.png` 는 서로 같은 그림이라 양 끝이 픽셀 단위로 맞습니다.

**정면 포즈는 색까지 한 장으로 통일해 둡니다.** PixelLab은 포즈·애니메이션을
만들 때마다 얼굴을 다시 그려서, 같은 캐릭터인데 눈매와 윤곽선 두께가 프레임마다 달라집니다
(예전에 `south` 계열은 눈이 노란 덩어리 + 굵은 검정 눈꺼풀, 회전 보간본은 흰자 + 호박색 홍채였습니다).
돌아선 뒤로는 머리도 다리도 움직이지 않으므로, `south.png` 를 기준으로

- **팔레트** — 생성 회차마다 후드 본색이 (35,36,35) / (30,30,30) 처럼 미묘하게 다릅니다.
  머리·다리만 바꿔 끼우면 그 경계에서 가슴을 가로지르는 **평평한 색 띠**가 생깁니다.
  그래서 먼저 모든 색을 `south.png` 팔레트로 치환합니다 (RGB 최근접, 단 후드 본색만
  "역할"로 손수 지정 — 거리로는 다른 색이 더 가깝습니다).
- `y < 106` (머리·후드·목) — `hold`, `raise-*`, `open-*` 전부 같은 그림
- `y >= 181` (다리·신발) — 같은 그림. 덤으로 bbox 아래끝이 247로 맞아 1px 수직 튐이 사라집니다
- `x 103~150, y 110~177` (가슴·주머니) — 같은 그림. 스프라이트 안에 그려져 있던 노트북을
  지운 자리가 평평한 판으로 남아 있었는데, 가슴은 어차피 안 움직이므로 통째로 덮습니다
  (손은 살색을 부풀려 보호합니다)
- `x 98~154, y 156~180` (밑단 아래) — 어느 포즈에서도 팔이 지나가지 않는 구간이라 더 넓게 덮습니다
- **지워지다 만 노트북 모서리** — PixelLab 이 `hold` 포즈 안에 노트북을 같이 그려 넣었고,
  예전 스크립트가 회색 몸통만 지워서 뚜껑의 좌우 모서리가 1px 검은 세로선으로 남아
  `x=94` 와 `x=157` 에 28행씩 서 있었습니다 (몸 중심에서 정확히 대칭 — 팔 윤곽은 이렇게 곧지 않습니다).
  안쪽 이웃 색으로 한 픽셀씩 덮어 지웁니다 (`scratchpad/deghost.py`).
- **노트북 색 낱픽셀** — 푸른 회색 (117,124,144) 계열은 기준 프레임 몸통에 하나도 없으므로,
  거기 있으면 노트북 조각입니다. 둘레 다수결 색으로 덮습니다 (`scratchpad/despeckle.py`).
- 마지막으로 **본체에서 떨어진 조각을 전부 지웁니다** — 위 세 단계에서 잘려 나간
  예전 후드 윤곽이 어깨 옆에 초승달처럼 뜨고, 기준의 팔 끝이 허리춤에 점으로 남습니다

으로 덮었습니다. 팔·손·노트북만 프레임마다 다릅니다. 스프라이트를 새로 뽑으면
이 통일 작업을 다시 해야 합니다 (`drawSprite`가 프레임마다 bbox 아래끝으로 발을 맞추기 때문에,
신발이 1px만 달라져도 캐릭터 전체가 위아래로 튑니다).

### 뚜껑을 여는 팔은 AI 보간이 아니라 직접 조립합니다

`open-0~8.png` 은 `tools/sprites/mkopen.py` 가 **raise 의 마지막 프레임 한 장에서** 만들어 냅니다
(`tools/sprites/base/raise-end.png` = `raise-11.png`).

> 처음에는 `hold.png` 를 바탕으로 썼는데, `hold` 는 **들어 올리기 전** 자세라 손이 6px 낮습니다.
> 그래서 raise 가 끝나는 #359 에서 open 으로 넘어갈 때 노트북이 툭 떨어졌습니다.
> 지금은 `open-0` 이 `raise-11` 과 3px(원본 소매 끝의 끊긴 줄 하나를 메운 것) 빼고 같은 그림이고,
> `raise` 가 끝나는 순간 바로 `openArm` 으로 넘어갑니다 — 사이에 `hold` 를 끼우지 않습니다.
> 노트북 자리도 맞췄습니다: raise 는 "두 손 한가운데", open 은 "잡은 손 + `flatW`/2" 로 계산하므로
> `flatW` 를 raise-11 의 두 손 간격(59.5px)에 맞춰야 옆으로도 안 튑니다. 지금 전환에서
> 노트북은 1px 만 움직입니다.

v3 보간으로 이 동작을 **세 번** 뽑아 봤지만 셋 다 같은 곳에서 무너졌습니다.
1. 예전 `open-0~6` — 손 덩어리가 83 → 171 → 252px 로 부풀면서 가로로 21px 순간이동했고,
   위팔이 몸통과 윤곽선으로 갈린 둥근 덩어리로 그려졌습니다.
2. `lid-open-arm` — 두 팔이 다 움직이고 눈까지 감겼습니다.
3. `lid-flip-from-raise` — raise 의 마지막 프레임을 시작 프레임으로 넣고 "나머지는 그대로"라고
   자세히 지시했는데도, 얼굴이 프레임마다 다시 그려지고(눈·앞머리·볼) 후드 조임끈이 사라졌으며,
   스프라이트 안에 **회색 노트북을 새로 그려 넣었습니다** — 노트북은 별개 오브젝트라 두 개가 됩니다.

세 번 다 같은 결론입니다. **정지해야 할 부위를 말로 막는 건 v3 에 안 먹힙니다.**

팔은 **새로 그리지 않습니다.** 원본 소매 픽셀을 곡선을 따라 **구부립니다.**
캡슐이나 스윕으로 새로 칠하면 두께·윤곽선·접힘선·어깨 주름이 전부 사라져서,
넘어가는 프레임에서 팔이 갑자기 뭉개져 보입니다 (실제로 #373 → #374 에서 그랬습니다).

1. **팔 없는 몸통 판** — `raise-end` 에서 오른팔·주먹(x ≥ 147, y 100~181)을 지우고
   그 자리에 옆선을 세웁니다. 팔이 지나가지 않는 y 146 아래는 원본 그대로 둡니다.
2. **뼈대** — 어깨 (153.5, 101) 고정. 손목은 `laptop/open-*.png` 에서 실측한 뚜껑 윗변을
   따라가고, 팔꿈치는 그 둘에서 나옵니다. 단 **옆으로 부푸는 양은 역기구학에 맡기지 않습니다** —
   곧게 편 상태에서 `h = √(L² − a²)` 는 0에서 기울기가 무한대라, 한 프레임 만에
   팔꿈치가 3.6px 튀어나오고 팔이 통째로 뚱뚱해집니다. `0 → 5px` 를 smoothstep 으로 줍니다.
3. **살 = 곡선 워프** — 새 곡선 기준으로 각 픽셀의 (호길이 u, 옆으로 떨어진 거리 off)를 구하고,
   원본 곡선의 같은 (u, off) 자리에서 색을 가져옵니다. 원본 픽셀이 그대로 오므로
   두께도 윤곽선도 접힘선도 반대쪽 팔과 같습니다.
   - 소매 폭은 원본을 u 마다 실측해 씁니다 (`measure_profile`).
   - 손이 있던 자리는 가장 가까운 소매 색으로 메워 둡니다. 안 그러면 구부린 소매에 1px 틈이 납니다.
   - 곡선을 손목 너머로 14px 연장합니다. 원본 소매 끝이 손목보다 아래에 있기 때문입니다.
   - 바깥 실루엣은 원본의 그 자리 색을 다시 찍습니다 — 반올림으로 한 칸 밀리면
     윤곽선(4,3,4)이 그늘색(19,17,25)으로 바뀌어 테두리가 흐려집니다.
4. **손** — `raise-end` 의 손을 그대로 옮깁니다. 프레임 수도 뚜껑과 같은 9장이라
   손과 뚜껑이 항상 같이 움직입니다.

검사는 넷입니다 — 연결 요소 1개, 팔레트 26색, y 95~170 에서 끊긴 행 0개, 오른쪽 살색 덩어리 1개.
거기에 **원본 대비 팔 폭**을 줄마다 찍어 줍니다 (지금 `open-1` 기준 평균 −0.5px).
`mkopen.py` 가 돌 때마다 스스로 검사하고 실패하면 종료 코드 1을 냅니다.

> `mkopen.py` 는 원본을 반드시 `tools/sprites/base/` 에서 읽습니다.
> `public/sprites/` 를 읽게 두면 자기 출력을 다시 먹어서 돌릴 때마다 팔이 1~2px씩 부풀었습니다.

#### 잔상이 생기던 세 군데

팔을 옮기는 편집은 "옮긴 자리"가 아니라 **"떠난 자리"** 에서 잔상이 납니다. 실제로 셋 나왔습니다.

1. **옛 주먹의 왼쪽 두 열** — 판을 만들 때 `x ≥ 151` 만 지웠는데 원본 주먹은 `x149` 까지 걸쳐
   있습니다. 손이 위로 올라간 프레임(`open-4` 이후)에서 그 두 열이 노트북 오른쪽 모서리에
   붉은 얼룩으로 남았습니다. 이제 `y133~156` 의 `x149~150` 도 지우고, 판을 만든 직후
   **"몸 오른쪽 아래에 살색이 0px"** 인지 검산합니다.
2. **캡슐이 원본 소매보다 넓은 자리** — 남은 본색이 소매 가장자리와 윤곽선 사이에 1px 밝은
   줄로 끼었습니다. 아직 본색인 채 실루엣 가장자리에 붙어 있으면 그늘색으로 내립니다.
3. **뚜껑 뒤로 넘긴 손** (`index.js`) — 뚜껑을 여는 손을 노트북 뒤에 그렸더니, 뚜껑의
   들쭉날쭉한 모서리에 주먹 왼쪽 열이 한 줄 걸렸다 말았다 하며 **화면 테두리에 붉은 점선**이
   생겼습니다. 주먹이 화면칸(DOM 오버레이) 바깥에만 걸치도록 자리를 잡았으므로 이제 앞에 그립니다.

검사는 렌더 프레임에서도 돌립니다 — **본체와 떨어진 40px 이하 조각**을 프레임마다 세어
`hold` 포즈(손대지 않은 원본)와 같은 것만 남았는지 봅니다.
고치기 전 손/노트북 구간에 8종 96회였던 것이 지금은 원본에도 있는 것들만 남았습니다.

**노트북은 캐릭터와 별개의 PixelLab 오브젝트입니다** (`public/sprites/laptop/`).

| 파일 | 내용 |
|---|---|
| `yaw-0~8.png` | 몸이 도는 만큼 노트북도 도는 9프레임. **8 = 넓은 면(옆모습으로 걸어올 때), 0 = 얇은 옆면(정면으로 돌아섰을 때)** |
| `tilt-0~8.png` | 세워 든 옆면이 화면 안에서 90도 돌아 가로로 눕는 9프레임 |
| `open-0~8.png` | 눕힌 채로 뚜껑이 열리는 자세 (9프레임) |

`yaw-8` = `tilt-0`, `tilt-8` = `open-0` 이라 세 묶음이 픽셀 단위로 이어집니다.

`yaw` 와 `tilt` 은 PixelLab 보간을 쓰지 않았습니다 — 뽑아 봤더니 중간 두 장에서
면 전체가 하얗게 떴다가 돌아오고 한 장은 속이 빈 윤곽만 나왔습니다. 대신 **PixelLab이
만들어 준 두 장**(넓은 면, 그리고 닫힌 판)에서 기하로 만들었습니다.

- `yaw` : 넓은 면과 옆면(닫힌 판을 90도 돌린 것)을 각도에 맞춰 가로로 줄여 나란히 붙입니다.
  정사영에서 보이는 폭이 `넓은면·sinθ + 두께·cosθ` 로 딱 떨어집니다.
  두 조각은 2px 겹칩니다 — 안 겹치면 가운데에 검은 윤곽선이 두 줄 생깁니다.
- `tilt` : 닫힌 판을 화면 안에서 돌린 것뿐입니다 (90도 회전은 픽셀 손실이 없습니다).

색이 원본 두 장뿐이라 프레임 사이에서 색이 튀지 않습니다.
`yaw` 는 회전 구간 진행도(`1 - turnP`), `tilt` 은 눕힌 정도(`laptopFlat`),
`open` 은 뚜껑이 열린 정도(`laptopOpen`)가 프레임 번호를 정합니다.

**노트북 스프라이트의 화면칸은 "꺼진 색"으로 칠해 뒀습니다.** 그 자리에 진짜 사이트를
DOM 으로 덮는데, 스프라이트가 밝은 하늘색이면 DOM 사각형이 1~2px만 어긋나도
그 틈으로 밝은 띠가 새어 나옵니다 (배율 0.5 로 그리는 좁은 화면에서는 64px 원본이
2:1 로 줄면서 가장자리가 한 픽셀씩 흔들립니다). 어두운 색끼리면 어긋나도 안 보입니다.

**노트북은 옆구리에 끼고 옵니다** — 넓은 면이 몸과 나란해서, 옆모습으로 걸어올 때는
그 면이 그대로 보이고 몸이 정면으로 돌아서면 같은 면이 옆으로 돌아가 얇은 옆면만 남습니다.
그 상태에서 두 손으로 눕히면 얇은 판이 화면 안에서 90도 돌아 가로로 눕습니다.
`tilt` 이 "면이 넘어가는" 그림이 아니라 "화면 안 90도 회전"인 이유입니다.

손 위치는 캐릭터 스프라이트에서 프레임마다 재고, 노트북 그림은 그 손자리에 얹습니다 —
그래서 노트북이 "따로 만든 물건인데 손을 따라 움직이는" 것으로 보입니다.
앵커(손이 잡는 자리)는 `draw.js` 의 `LAP` 에 실측값으로 적혀 있습니다.
`tilt` 은 프레임마다 그림 중심이 앵커고(넘어가면서 무게중심이 옮겨 갑니다),
`open` 은 두 손이 본체를 잡은 채 뚜껑만 열리므로 9프레임이 같은 앵커를 씁니다.
화면(패널) 자리도 프레임별로 재서 `LAP.screen` 에 넣어 뒀습니다 —
진짜 사이트를 띄우는 DOM 오버레이가 그 사각형을 따라갑니다.

방과 전등은 캔버스에 코드로 그립니다. 걸음이 미끄러지지 않게 하는 규칙 셋:

- 걷기 프레임은 시간이 아니라 **이동 거리**에 묶여 있다 (프레임당 17.1px = 실측 보폭의 절반).
- 프레임을 놓는 기준점은 그림 영역의 한가운데가 아니라 **머리 중심**이다.
  팔다리가 벌어지면 bbox 중심이 13px씩 흔들려서 몸이 앞뒤로 덜컥거렸다.
- 걷는 거리를 한 주기 단위로 올림해서, 마지막 걸음이 **두 발 모은 프레임**에서 끝난다.
- 걷다 서는 순간 팔이 제자리로 돌아오며 손이 13px 튀므로, 그 0.16초만 두 위치를 섞는다.
- 매달린 노트북은 팔의 위아래 흔들림을 1/3만 따라간다 (13px → 4.7px).

그레인(잡티)은 **배경에만** 깐다. 화면에 고정된 잡티를 캐릭터·노트북 위까지 깔면
그것들이 움직일 때마다 다른 픽셀이 덮여, 윤곽선과 평평한 면이 프레임마다 지글거린다.

> `src/scripts/intro/`(three.js 3D 버전)과 `assets/3d/character.glb`는 이전 시안입니다.
> 어디서도 import하지 않으므로 빌드 결과물에는 들어가지 않습니다.

## 게임 덱 (홈 메인)

인트로가 끝나면 나오는 화면의 본론입니다. 게임 목록을 격자로 늘어놓는 대신,
**카드 한 장씩 넘겨 보는** 구성 — 레퍼런스는 Hello Monday의
[How to Talk to White Kids about Racism](https://howtotalktowhitekidsaboutracism.com/)입니다.
그 사이트에서 가져온 것은 다음 여섯 가지입니다.

1. 어두운 무대 한가운데 원근감 있는 오브젝트 하나 + 그 아래 바닥 그림자
2. **무대에는 그것 말고 아무것도 없다** — 섹션 제목도, 설명도, 더 보기 링크도 없다
3. 카드마다 **고유색**이 있고, 넘길 때마다 무대에 번지는 빛이 그 색으로 흐른다
4. 인디케이터 점이 각자 자기 카드의 색을 갖는다
5. 화면 양 끝의 얇은 화살표 + 드래그 + 휠 + 키보드, 네 가지 넘기는 법
6. 캡션이 한 줄씩 밀려 들어오는 등장 리듬

**덱에는 게임만 들어갑니다.** 블로그는 홈에서 빼고 `/blog`에만 둡니다.

### 카드 위에 있는 것

키아트 + **레터링**(생성한 픽셀 폰트, 왼쪽 위) + **바로 플레이 버튼**(왼쪽 아래), 이 셋뿐입니다.
설명도 태그도 없습니다. 상단 바는 어느 페이지에도 없습니다.

**카드 앞면 전체가 게임으로 가는 링크**이고, 버튼은 그 위에 얹힌 "보이는 손잡이"입니다
(`pointer-events: none`). 링크 안에 링크를 넣을 수 없기 때문이기도 하고, 이러면
카드 어디를 눌러도 게임이 열립니다.

#### 버튼은 두께가 있습니다

참고한 건 [Collect UI 의 "Confirm?"](https://collectui.com/designs/button-ui-design-inspiration/54b610d1-1fd6-4d6c-ace5-4e43f27f6b42)
(reijowrites) 입니다. **바닥판은 제자리에 있고 뚜껑만 6px 떠 있다가, 누르면 바닥까지 내려앉습니다.**

바닥판은 `.gc-play::before` 로 깔고, 뚜껑은 `transform: translateY(-6px)` 로 띄웁니다.
높이를 바꾸지 않고 transform 만 쓰므로 눌러도 레이아웃이 흔들리지 않습니다.

**뚜껑은 맑은 유리입니다** — 자기 색이 없고, 뒤의 키아트를 흐려서 그대로 통과시킵니다
(`backdrop-filter: blur(16px) saturate(185%) brightness(1.04)`).

> 예전에는 카드 색을 40% 로 덮어서 **색유리**처럼 보였습니다. 유리는 자기 색을 갖지 않아야
> 뒤가 비쳐 보입니다. 지금 얹는 건 흰 막 12% 와 어두운 막 20% 뿐입니다.

유리로 읽히게 하는 건 결국 **가장자리**입니다. 세 줄이 전부입니다.

| 자리 | 값 | 역할 |
| :--- | :--- | :--- |
| 윗변 | `inset 0 1px 0 rgba(255,255,255,.5)` | 빛이 떨어지는 쪽 모서리 |
| 테두리 | `inset 0 0 0 1px rgba(255,255,255,.2)` | 유리 두께 |
| 아랫변 | `inset 0 -1px 0 rgba(0,0,0,.28)` | 반대쪽 모서리 |

여기에 비스듬히 스치는 빛 한 줄(`::after` 의 105도 그라데이션)을 얹으면 판이 아니라 유리로 보입니다.

**흰 글씨는 실제로 재서 맞췄습니다.** 키아트를 캔버스에 그려 버튼이 놓이는 자리의 밝기를 재고,
유리 합성까지 계산해 대비를 봤습니다 — 흰 막 16% / 어두운 막 16% 일 때는 **4.4:1** 로 기준(4.5:1)에
못 미쳤고, 12% / 20% 로 바꾸니 **5.3~5.7:1** 이 나옵니다. 글자 그림자는 그 위에 덤입니다.

> 투명 효과를 줄이길 원하는 사람에게는(`prefers-reduced-transparency`) 유리를 걷고
> 불투명한 판(`rgba(10,10,16,.86)`)으로 바꿉니다. 흐림이 빠지면 글씨가 그림 위에 그대로 놓입니다.

> **부모에 `filter` 를 걸면 안 됩니다.** `filter` 는 backdrop-root 를 만들어서 자식의
> `backdrop-filter` 가 그 밖(=카드 그림)을 못 보게 됩니다. 처음엔 `.gc-play` 에
> `drop-shadow` 를 썼는데 그래서 유리가 안 비쳤습니다. 그림자는 바닥판의 `box-shadow` 로 옮겼습니다.

> **transform 주인이 한 요소에 하나씩이어야 합니다.** 이 버튼만 세 겹입니다:
> `.gc-cta`(등장 연출) → `.gc-play`(커서 시차) → `.gc-play-cap`(눌림).
> 한 요소에 몰면 서로 덮어씁니다.

여기서 두 번 걸려 넘어졌습니다.

1. **브라우저의 "링크 끌어다 놓기"가 드래그를 가로챕니다.** 앞면이 `<a>` 가 되는 순간
   카드를 옆으로 끌 수 없게 됩니다. `draggable="false"` 와 `-webkit-user-drag: none`,
   그리고 이미지에 `pointer-events: none` 을 줘야 합니다.
2. **`pointerdown` 에서 바로 `setPointerCapture` 를 하면 카드를 눌러도 게임이 안 열립니다.**
   포인터가 캡처되면 뒤이은 `click` 이 캡처 대상(무대)으로 가서 링크에 닿지 않습니다.
   캡처는 **실제로 4px 이상 움직인 순간**에만 겁니다 (`beginDrag()`).
   같은 이유로 `state.dragging` 도 그때 켜야 합니다 — 누르자마자 켜면 render 가 카드에
   `pointer-events: none` 을 걸어 버립니다.

사이트의 다른 곳으로 가는 길은 아래 **아이콘 줄**이 냅니다 — 모든 페이지에서 같은 줄입니다.

### 카드 그림이 움직입니다

키아트는 정지 이미지가 아니라 **9프레임 루프**입니다. 커서를 올린 동안만 돕니다.

| 카드 | 움직임 |
| :--- | :--- |
| Aimbooster | 네온 링이 숨 쉬듯 밝아졌다 어두워지고, 격자 바닥에 반사가 번진다 |
| Coming Soon | 매달린 전구가 깜빡이고 캐비닛 화면이 켜졌다 잦아든다 |

`animate_image(first_frame_url=..., action="...")` 로 뽑았습니다.
프레임들은 `tools/emblem-sheet.py` 로 가로 시트 한 장(2304×160)이 되고,
`background-position-x` 를 `steps(9, jump-none)` + `alternate` 로 넘깁니다.
`<img>` 를 여러 장 겹치지 않기 때문에, 3D 로 기울어진 채로도 합성 비용이 거의 없습니다.

멈출 때는 `animation` 을 끄지 않고 `animation-play-state` 만 `paused` 로 둡니다.
`animation` 자체를 껐다 켜면 매번 0번 프레임으로 튀지만, 재생 상태만 바꾸면
멈췄던 그 프레임에서 그대로 이어집니다. 손가락으로 보는 화면에는 호버가 영영 오지 않으므로
`@media (hover: none)` 에서는 계속 돌려 둡니다.

**애니메이터는 한 변 256px 까지만 받습니다** (`width × height × frame_count ≤ 524288` 도 같이).
그래서 키아트를 256×160 으로 새로 뽑았습니다 — 기존 400×248 을 줄여 넣으려 했지만
base64 가 9~18k 자였고, 그 크기는 툴 인자로 넘기다 깨집니다. PixelLab 이 자기 결과물을
`https://api.pixellab.ai/mcp/images/{id}/download` 로 호스팅하므로, **URL 을 그대로 넘기는 게**
base64 를 만질 필요가 없는 유일한 길입니다.

> **"조명만 바뀌는" 동작을 시켜야 합니다.** 캐비닛(덩어리가 크고 속이 찬 그림)은 9프레임 내내
> 구도가 완벽히 유지됐고 빛만 변했습니다. 네온 쪽은 링 크기가 프레임마다 조금씩 출렁이는데,
> 네온 간판의 깜빡임으로 읽혀서 그대로 뒀습니다. 형태가 바뀌면 안 되는 그림이라면
> 프롬프트에 "everything else stays perfectly still" 을 넣고 결과를 프레임 단위로 확인하세요.

### 카드에 두께가 있습니다

앞면 뒤 **32px** 에 판(`.gcard-slab`)을 하나 두었습니다. `preserve-3d` 안이라 커서로 기울이면
원근이 알아서 옆면을 만들어 줍니다. 18px 로는 실제 기울기(약 9도)에서 2~3px 밖에 안 드러나
보이지 않았습니다.

> **이 판도 앞뒷면과 같이 흐려져야 합니다.** render() 가 `.gcard-front` 와 `.gcard-back` 의
> opacity 만 쓰고 있었는데, 그러면 카드가 흐려지는 동안 이 판만 남아 **카드 색 사각형이
> 화면을 덮습니다.** 등장 연출과 넘기는 중에 그대로 드러났습니다.

> **숨은 탭에서는 등장 연출을 시작하지 않습니다.** 백그라운드 탭은 rAF 가 멈춰서 카드가
> 안 보이는 채로 굳습니다 (새 탭으로 열어 둔 경우). `visibilitychange` 를 기다렸다가 깝니다.

### 카드에 커서를 올리면 나타나는 엠블럼

카드마다 그 게임을 상징하는 **움직이는 픽셀 엠블럼**이 오른쪽 위에 떠오릅니다.
전부 PixelLab 으로 만들었습니다.

| 카드 | 엠블럼 | 움직임 |
| :--- | :--- | :--- |
| Aimbooster | 분홍 네온 크로스헤어 | 팔과 모서리 눈금이 안으로 모이고 중심이 밝아진다 |
| Coming Soon | 작은 아케이드 캐비닛 | 꺼진 화면이 앰버로 켜진다 |

**포즈 네 장을 한 번에 주문합니다.** `create_1_direction_object(size=64, item_descriptions=[...])`
한 번이면 후보 16장이 같은 화풍으로 나옵니다 (20 generations). 따로따로 뽑으면 화풍이 어긋납니다.
쓸 것만 `select_object_frames` 로 골라내면 각각 독립된 오브젝트가 됩니다.

재생은 9프레임 가로 스프라이트 시트 한 장 + `steps(9, jump-none)` + `alternate` 입니다.
되감아 돌아오므로 시작과 끝이 같은 그림이고, 이음매가 생길 수 없습니다.
`jump-none` 이라야 0% 와 100% 를 모두 밟습니다 — 그냥 `steps(9)` 면 마지막 프레임을 건너뜁니다.

#### v3 보간은 가느다란 그림에서 무너집니다

아케이드 캐비닛(덩어리가 큰 그림)은 `animate_object(mode='v3', end_frame_base64=...)` 로
9프레임이 깔끔하게 나왔습니다. 그런데 **크로스헤어는 못 썼습니다** — 프레임마다 획이 통째로
사라지고 모양이 제각각이라, 재생하면 깜빡이는 것처럼 보였습니다.
가늘고 빈 곳이 많은 그림은 모델이 붙잡을 게 없습니다.

그래서 크로스헤어는 **원본 픽셀을 옮겨서 직접 조립**했습니다 (`tools/emblem-slide.py`).
두 포즈가 같은 중심을 기준으로 대칭이고 바깥 조각이 안으로 모일 뿐이므로,
조각을 방향별로 묶어 실측한 거리만큼 **정수 픽셀로** 밀면 됩니다. 정수라서 리샘플링이 없고
도트가 뭉개지지 않습니다. 중심부만 두 포즈를 알파로 교차시킵니다.

> **방향을 나눌 때 캔버스 한가운데를 쓰면 안 됩니다.** 그림이 1px 만 아래로 치우쳐 있어도
> 가로팔이 "왼쪽아래 대각선"으로 분류돼 엉뚱한 방향으로 움직입니다.
> 그림 자신의 무게중심을 쓰고, 2.5px 정도의 데드존을 둬야 합니다.

> 같은 색 위에 같은 색을 얹으면 묻힙니다 (분홍 카드 위 분홍 크로스헤어).
> 짧은 검정 `drop-shadow` 를 두 겹 겹쳐 도트 윤곽을 따라 테두리를 만들면 떨어져 보입니다.

### 아래 아이콘 줄 (사이트의 유일한 메뉴)

참고한 건 [Collect UI 의 expanding tab item](https://collectui.com/designs/button-ui-design-inspiration/ce63a499-08b0-4782-866c-f99d0b7adc5b)
(Nitish Khagwal) 입니다. 쉴 때는 아이콘만 든 동그란 알약, **커서를 올린 하나만** 옆으로
늘어나면서 이름이 드러납니다.

늘어나는 건 `width` 가 아니라 **`max-width: 0 → 10rem`** 입니다. `width: auto` 는 트랜지션이
안 걸리고, `width` 를 직접 바꾸면 옆 알약들이 매 프레임 다시 배치됩니다.
이름은 `overflow: hidden` 으로 잘려 있다가 0.06초 늦게 페이드인합니다 — 알약이 먼저 열리고
글씨가 따라 들어와야 "펼쳐지는" 느낌이 납니다.

**아이콘 넷은 이 사이트를 위해 직접 그렸습니다** (`src/components/Footer.astro` 안에 SVG 문자열).
규칙은 하나입니다: **24×24 격자, 선 굵기 1.7, 끝과 이음은 둥글게.** 카드 옆 화살표와 같은 식구입니다.

| | 아이콘 |
| :--- | :--- |
| 게임 | 게임패드 (둥근 몸체 + 십자키 + 버튼 두 개) |
| 블로그 | 공책 (제본선 + 글줄) |
| 소개 | 매달린 전구 — 이 사이트의 마크 그대로 |
| 인트로 다시 보기 | 한 바퀴 도는 화살표 |

> 전구를 **동그라미로 그리면 돋보기처럼 보입니다.** 어깨가 좁아지는 진짜 전구 실루엣이어야
> 전구로 읽힙니다. 24px 짜리 글리프에서는 실루엣이 전부입니다.

> **상단 바는 어디에도 없습니다.** 홈·블로그·소개 모두 이 아이콘 줄 하나로 다닙니다.
> 글자 푸터(서명 + 저작권 줄)도 없앴습니다 — 페이지마다 아래 모습이 달라지지 않게 하려고요.
> 메일 주소는 소개 페이지 본문에 둡니다.

### 홈은 한 화면입니다 (스크롤 없음)

`<Layout fit>` 이 켜지면 `<html>` 에 `data-fit` 이 붙고, `#page` 가
`height: 100dvh` 짜리 3단 그리드(헤더 / 본문 / 구석 푸터)가 됩니다. 본문은 다시
2단(히어로 / 덱)이라 **덱은 "남은 높이"를 그대로 물려받습니다.**

- 위쪽에는 마크 하나뿐입니다 (전구 + 이름, 약 93px). 여기서 아낀 픽셀이 그대로 카드 크기가 됩니다.
- 푸터(아이콘 줄)는 오른쪽 아래 구석에 작게 앉습니다. 다른 페이지에서도 같은 자리입니다.
- **카드 크기는 컨테이너 쿼리 단위로 잽니다.**
  `width: min(880px, 100cqw, calc(100cqh * var(--ar)))` + `aspect-ratio` —
  무대(`.deck-stage`)에 `container-type: size` 를 걸어 가로·세로를 둘 다 재게 한 것입니다.
  `aspect-ratio` + `height: 100%` + `max-width` 조합은 **쓰면 안 됩니다** — 폭만 잘리고
  높이는 그대로 남아서 비율이 깨지거나 좁은 화면에서 카드가 밖으로 삐져나갑니다.
- **너무 낮은 화면(560px 이하)에서는 스크롤로 풀립니다.** 억지로 맞추면 카드가 우표만 해집니다.
  이때 무대는 부모에게서 높이를 못 받으므로 `.deck-stage` 에 직접 높이를 줍니다
  (안 주면 `100cqh` 가 0 이 돼 카드가 통째로 사라집니다).
- **`ch` 단위로 한글 줄바꿈을 잡지 마세요.** `ch` 는 "0" 한 글자 폭이라 한글에서는 실제 폭의
  절반쯤으로 잡힙니다. 한 줄로 끝내야 하는 문장은 `rem` 으로 재세요.


### 마크는 전구 하나와 이름 하나입니다

예전에는 `새벽 세 시, 불은 아직 켜져 있다.` 한 줄이 있었습니다. 지금은 **마크**가 그 자리에 섭니다.
참고한 것은 [Aura 의 로고 에셋 모음](https://www.aura.build/assets?q=logo&order=popular)입니다 —
인기 있는 것들은 하나같이 **검은 판 한가운데 놓인 마크**이고, 심볼 + 워드마크가 세로로 쌓인
단순한 잠금 구조였습니다. 화려한 것보다 가운데에 조용히 놓인 쪽이 오래 봅니다.

그래서 이렇게 짰습니다.

```text
      │      ← 줄: 화면 맨 위(top: 0)에서 내려온다
      ●      ← 전구: 이 사이트의 마크
   my·site   ← 이름: Studio Marquee (이 사이트를 위해 만든 픽셀 폰트)
```

- **줄은 화면 맨 위에서 시작합니다.** 마크를 배지처럼 얹지 않고 방의 천장에 매답니다.
  인트로의 노트북 화면 안에서도 같은 컴포넌트를 쓰므로, 작은 화면 속에서도 천장에서 내려옵니다.
- **마크가 곧 이 페이지의 광원입니다.** 배경의 빛도 같은 자리(화면 위 가운데)에서 원뿔로 떨어지고,
  전구는 배경과 **같은 키프레임**(`lamp-breathe`, 8.5초)으로 숨 쉽니다. 광원이 둘로 보이지 않습니다.
- 이름은 **Studio Marquee**로 찍습니다. 라틴만 있는 폰트인데 이름이 라틴이라 마침 맞습니다.
  가운데 점(`·`)은 그 폰트에 없어서 본문 글꼴로 떨어지고, 그 한 글자만 전구색입니다.
- `<h1>`이 그대로 마크입니다. 화면에 보이는 글자가 `my·site` 라서 스크린리더도 같은 것을 읽습니다.

### 모든 페이지가 같은 틀을 씁니다

위는 마크, 아래는 아이콘 줄. 이 둘은 페이지가 바뀌어도 그대로고, **가운데만 바뀝니다.**

```text
        ●  my·site        ← 마크 (모든 페이지 공통, Layout 이 얹는다)
  ┌──────────────────┐
  │   페이지 머리      │    ← 블로그·글·소개에만 있다
  │   내용            │    ← 덱 / 선반 / 읽는 칸
  └──────────────────┘
        ⌂ ▤ ♁ ↻        ← 아이콘 줄 (모든 페이지 공통)
```

마크는 `Brand.astro` 하나이고 `Layout.astro` 가 모든 페이지에 얹습니다.

- **홈에서는 `<h1>`**, 다른 페이지에서는 **홈으로 가는 `<a>`** 입니다. 그 페이지의 `h1` 은 따로 있으므로
  제목을 두 개 두지 않습니다. 상단 바를 없앤 뒤로 홈으로 가는 길이 아이콘 줄 하나뿐이었는데, 이걸로 하나 늘었습니다.
- 누를 수 있는 쪽(`<a>`)은 커서를 올리면 **불이 조금 더 밝아집니다.** 초점 링도 따로 잡아 뒀습니다.
- 인트로의 노트북 화면 안에서도 같은 컴포넌트를 씁니다. 화면이 사이트로 넘어갈 때 마크가 그대로 이어집니다.

#### 칸은 둘 아니면 셋입니다

```css
html[data-fit] #page > .main { grid-template-rows: auto 1fr; }                     /* 마크 + 덱 (홈) */
html[data-fit] #page > .main:has(> :nth-child(3):not(script):not(style)) {
	grid-template-rows: auto auto 1fr;                                             /* 마크 + 머리 + 내용 */
}
```

여기서 두 번 걸려 넘어졌습니다.

> **`<script>` 도 자식으로 세어집니다.** Astro 가 컴포넌트 끝에 붙이는 스크립트 때문에 홈이
> `[마크 + 덱 + 스크립트]` 셋으로 읽혀서, 덱이 `auto` 칸에 들어가 **120px 로 납작해졌습니다.**
> `:not(script)` 를 넣어야 합니다.

> **flex 로 늘리면 안 됩니다.** 처음엔 칸 수에 상관없게 하려고 `.main` 을 세로 flex 로 바꾸고
> 마지막 자식에 `flex: 1` 을 줬는데, 덱이 `container-type: size` 로 높이를 재기 때문에
> **flex-grow 로 생긴 높이에는 안쪽 `100%` 가 기대지 못해 카드가 0px** 이 됐습니다.
> 격자의 `1fr` 은 확정 높이라 그 문제가 없습니다.

> **`.main` 자신에게도 `min-width: 0` 이 필요합니다.** 격자 칸의 기본값(`auto`)이면 안에 든
> 가로 스크롤 영역이 칸을 밀어내서, 375px 화면에서 `.main` 이 1120px 까지 자랐습니다.
> 마크는 그 안에서 가운데 정렬돼 있었으므로 **화면 밖(x≈526)으로 밀려 나가 보이지 않았습니다.**


### 카드 고르개는 맥 독입니다

아래쪽 인디케이터는 두 가지 모습을 오갑니다. 참고한 건
[Collect UI 의 hover-state 한 편](https://collectui.com/designs/hover-state-ui-design-inspiration/b13f037a-5eaa-4ed3-8b52-da37956725a0)
(Moiz Arshi) 입니다.

| | 쉴 때 | 커서가 오면 |
| :--- | :--- | :--- |
| 모양 | 카드 색 점 | 그 게임의 키아트 타일 |
| 알약 | 납작하게 눌린 상태 | 제 높이로 펴짐 |
| 이름 | 없음 | 가장 가까운 타일 위에 이름표 |

**`--open` 하나가 0↔1 로 가면 나머지는 CSS 가 알아서 합니다.** `@property` 로 등록해 뒀기 때문에
CSS 가 직접 보간해 주고, JS 는 커서가 독 근처에 들어왔는지만 판단해서 0 또는 1 을 씁니다
(매 프레임 쓰면 트랜지션이 계속 처음부터 다시 시작되므로, **값이 바뀔 때만** 씁니다).
점 ↔ 타일 모핑은 `border-radius: calc(50% - var(--open) * 38%)` 와
`transform: scale(calc(0.24 + var(--open) * 0.76))`, 키아트의 `opacity: var(--open)` 세 줄이 전부입니다.

확대는 독 그대로 smoothstep 낙하 곡선입니다 — 커서에서 116px 안쪽 타일이 거리에 따라 함께 부풉니다.
**확대는 `.dock-lift` 안쪽에서만** 일어납니다. 버튼 자체를 키우면 이름표까지 같이 커집니다.

레이아웃이 한 화면이라 이름표가 앉을 자리가 빠듯합니다. 카드와 독 사이 여백,
타일이 솟는 높이, 이름표 높이가 서로 맞물려 있으니 **셋 중 하나를 건드리면 나머지도 재야 합니다.**

### 상태는 실수 하나

인트로와 같은 원칙입니다 — 보이는 모든 것이 **덱 위치 `pos` 의 순수 함수**입니다.
`pos`가 정수가 아니어도 되므로 (0.5 = 반쯤 넘어간 상태) 드래그 중이든 스프링으로
되돌아오는 중이든 `render()` 하나가 전부를 그립니다. 넘기기는 `pos`를 다음 정수로
스프링 보간하는 것뿐입니다.

`anime.js` v4는 **스프링 감속과 stagger만** 빌려 씁니다. 매 프레임 그리는 일은 직접 합니다.

### 커서에 반응하는 부분 (`deck/pointer.js`)

핵심은 **"층마다 따라오는 속도가 다르다"** 하나입니다.

| 층 | 방향 | 따라오는 시간 |
| :--- | :--- | ---: |
| 키아트 | 커서와 **반대로** | 1150ms |
| 캡션 | 커서 쪽으로 | 720ms |
| 레터링 | 커서 쪽으로, 제일 많이 | 520ms |
| 판 전체 (기울기) | 커서 쪽으로 | 620ms |
| 판 전체 (끌림 / 기우뚱) | 커서 쪽으로 | 1000ms |

마우스를 빠르게 그으면 층이 갈라졌다가 멈추면 다시 한 장으로 모입니다. 이게 카드를
평면이 아니라 두께를 가진 물건으로 읽히게 만듭니다. 여기에 **가로 속도로 기우뚱하는 각도**
(코너를 도는 것처럼), **커서 자리에 맺히는 반사광**, **가까이 가면 끌려오는 화살표**가 붙습니다.

값이 초당 수십 번 바뀌는 자리이므로 `animate()` 가 아니라 anime.js 의
**`createAnimatable`** 을 씁니다. 속성마다 duration 을 따로 줄 수 있어서 위 표가 그대로 코드가 됩니다.

**카드를 까는 시점은 인트로가 끝나는 순간입니다.** 인트로의 노트북 화면 안에는 히어로까지만
들어 있어서, 미리 깔아 두면 화면이 사이트로 넘어갈 때 카드가 이미 놓인 채로 툭 나타납니다.
`deck/index.js` 가 `data-intro` / `site-revealed` 를 `MutationObserver` 로 지켜보다가,
인트로가 끝나는 그 프레임에 깝니다. 그러면 그게 곧 등장 연출이 됩니다.

**transform 의 주인은 요소마다 하나뿐입니다.** `deck-tilt` 는 pointer.js, `gcard` 와
`gcard-inner` 는 render(), `deck-scene` 은 render() 의 부유 애니메이션. 겹치면 서로 덮어씁니다.

### 걸려 넘어진 것들

- **카드에는 `opacity`를 걸면 안 된다.** `opacity < 1`이면 `preserve-3d`가 납작해져서,
  90도를 넘어간 순간 뒷면 대신 **거울상 앞면**이 보인다. 투명도는 앞/뒷면 각각에만 준다.
  같은 이유로 뒤 카드를 어둡게 할 때도 `filter: brightness()` 대신 검은 판(`.gcard-dim`)을 덮는다.
- **회전은 `.gcard-inner`가 맡는다.** 바깥(`.gcard`)은 덱에서의 위치만 옮긴다.
  뒷면 컬링은 회전을 가진 요소의 좌표계에서 결정되므로, 회전과 투명도가 같은 요소에 있으면 안 된다.
- **넘어간 카드는 일찍 사라져야 한다.** 왼쪽 모서리를 축으로 도는 카드는 화면을 가로질러
  섹션 제목까지 덮는다. `t=0.6`부터 흐려지고 왼쪽 아래로 빠지게 해서 어둠에 녹인다.
- **휠은 덱이 화면 한가운데 있을 때만 가로챈다.** 그리고 양 끝에 닿으면 페이지 스크롤에
  그대로 넘긴다 — 안 그러면 덱에서 스크롤이 갇힌다.
- **기울어진 요소의 `getBoundingClientRect()` 를 읽으면 안 된다.** 그 값이 다시 기울기를
  바꾸고, 바뀐 기울기가 다시 rect 를 바꾼다 (되먹임). 변형이 걸리지 않는 `deck-stage` 에서
  읽고, 판의 크기는 레이아웃 값인 `offsetWidth/Height` 로 구한다.
- **되돌리기는 무대가 아니라 창을 벗어날 때.** 커서는 화면 어디에 있든 카드에 영향을 주므로
  (레퍼런스의 떠 있는 책처럼), 무대 `pointerleave` 로 되돌리면 나가자마자 되돌리고
  다음 `pointermove` 가 다시 기울여서 둘이 싸운다.

### 그래픽 · 타이포

전부 PixelLab MCP로 이 사이트를 위해 새로 만든 것입니다.

| 파일 | 만든 법 |
| :--- | :--- |
| `public/art/aimbooster.png` · `coming-soon.png` | `create_image_pixflux` 400×248 (크기는 4의 배수여야 한다) |
| `public/art/card-back.png` | 같은 도구 64×64, 카드 뒷면 타일 무늬 |
| `public/fonts/studio-marquee.ttf` | `create_font` 32px Bold — 카드 레터링 전용 |
| `public/art/emblem-*.png` | `create_1_direction_object` 로 포즈 4장 → 9프레임 시트 (아래 참고) |

키아트는 `object-fit: cover` + `image-rendering: pixelated`로 2~3배 확대해 씁니다.
폰트는 `unicode-range: U+0020-007E`로 **라틴만** 받게 잠가 뒀습니다 — 한글 글리프가 없어서
잠그지 않으면 한글이 두부로 나옵니다.

### 글자 규칙 (한글 기준)

화면에 쓰는 크기는 `global.css` 의 사다리에서만 꺼내 씁니다. 제각각인 값(0.62 / 0.66 / 0.72 / 0.88…)이
쌓이면 같은 무게여야 할 글씨가 화면마다 달라 보입니다.

| 토큰 | 크기 | 쓰는 곳 |
| :--- | ---: | :--- |
| `--fs-micro` | 11px | 모노 라벨 (BY · 분류 칩) |
| `--fs-mono` | 12px | 날짜 · 개수 |
| `--fs-xs` | 13px | 보조 설명 · 알약 글씨 |
| `--fs-sm` | 15px | 카드 설명 |
| `--fs-base` | 16px | 기본 |
| `--fs-md` | 17px | 카드 제목 · 읽는 본문 |
| `--fs-lg` | 19px | 작은 제목 |
| `--fs-xl` | 23px | 글 안의 소제목 |

한글이라서 다르게 잡은 것 넷:

- **표제 줄 간격은 1.28**(디스플레이 1.1~1.2)입니다. 영문 기준의 1.05 로 두면 받침이 윗줄 글자에 닿습니다.
- **본문 줄 간격은 1.8**, 한 줄에 **한글 40자 안팎**(760px 단 × 17px)입니다.
- **폭을 `ch` 로 재지 않습니다.** `ch` 는 "0" 한 글자 폭이라 한글에서는 실제의 절반으로 잡힙니다.
  리드는 `rem`, 큰 카드 제목은 `em`(한글 한 글자 = 1em)으로 잽니다.
- 자간은 큰 글씨일수록 좁힙니다 (h1 −0.04em → 본문 −0.003em). 작은 한글에 음수 자간을 크게 주면 뭉칩니다.

날짜·개수처럼 모노로 찍는 숫자에는 `font-variant-numeric: tabular-nums` 를 겁니다.
안 그러면 카드마다 날짜 폭이 미세하게 달라 세로줄이 흔들립니다.

### 대비와 누르는 크기

글자색은 배경(`#0A0A0F`) 대비를 재서 정했습니다.

| 토큰 | 대비 | 용도 |
| :--- | ---: | :--- |
| `--text` | 16.6:1 | 제목 · 본문 |
| `--text-dim` | 7.0:1 | 설명문 |
| `--text-mute` | 5.7:1 | 날짜 · 보조 정보 |
| `--text-faint` | 3.4:1 | **글자 금지** — 쉬고 있는 아이콘·선 같은 장식 전용 |

> `--text-mute` 는 원래 `#65646F`(3.4:1)였습니다. 카드 설명처럼 실제로 읽는 글에 쓰고 있었는데
> 본문 기준 4.5:1 에 못 미칩니다. `#8A8894`(5.7:1)로 올렸습니다.

누르는 것은 **40px 아래로 내리지 않습니다** (손가락으로 쓰는 화면에서는 44px). 아이콘 줄, 분류 알약,
"전체 보기" 알약이 모두 여기에 맞춰져 있습니다.


게임을 추가할 때 `src/content/games/*.md`에 넣을 수 있는 덱 전용 항목:

```yaml
art: '/art/내게임.png'      # 카드 전면 키아트
accent: '#F32BC8'           # 이 카드의 색 (빛 · 점 · 버튼)
lettering: 'MY|GAME'        # 카드 위 큰 글씨, | 가 줄바꿈
```

### 어두운 화면의 깊이는 그림자가 아니라 면입니다

참고한 것은 [getdesign.md](https://getdesign.md/) 의 DESIGN.md 분석 두 건입니다 —
**Lamborghini**(검정 바탕 + 금색 액센트)와 **Linear**(어두운 면 사다리 + 절제).
둘 다 같은 말을 합니다: **거의 검은 바탕에서는 검은 그림자가 보이지 않는다.**

그래서 떠 있는 것을 그림자로 띄우지 않고 **바탕보다 밝은 면**으로 올립니다.

| 층 | 색 | 쓰는 곳 |
| :--- | :--- | :--- |
| 0 바탕 | `--bg` `#0A0A0F` | 페이지 |
| 1 카드 | `--surface` `#101017` | 글 카드 · 알약 |
| 2 들린 카드 | `--surface-2` `#15151F` | 커서가 올라간 카드 · 알약 |
| 3 안쪽 블록 | `--surface-3` `#1C1C27` | 코드블록 · 입력창 |

여기에 **윗변 1px 빛**(`--edge-hi`)을 더합니다. 전등이 위에 있으니 밝은 모서리는 윗변 하나뿐이어야 합니다.
카드의 세로 그라데이션과 앰버 글로우 그림자는 걷어냈습니다.

### 배경은 전등 하나입니다

층이 셋입니다.

1. **원뿔** — 위에서 좁게 내려와 아래로 퍼지는 빛. 타원형 얼룩이 아니라 원뿔이라야 "매달린 전등"으로 읽힙니다.
2. **바닥빛** — 아래쪽에 고이는 아주 옅은 반사.
3. **비네트** — 네 귀퉁이를 눌러 화면을 무대처럼 가둡니다.

색은 전구색 하나뿐입니다. 예전에 아래쪽에 깔려 있던 **보라색 광원은 이유가 없어서 지웠습니다**
(광원이 둘이면 "전등 하나 켜진 방"이 아닙니다). 전구는 8.5초에 한 번 숨 쉬듯 밝기가 흔들리고,
`prefers-reduced-motion` 에서는 멈춥니다.

### 표제 무게를 한 단계 내렸습니다

`900` 은 화면에 대고 소리를 지르는 무게입니다. 어두운 바탕에서는 글자가 실제보다 굵어 보이기까지 합니다.

| | 전 | 후 |
| :--- | ---: | ---: |
| h1 | 900 | **720** |
| h2 | 800 | 690 |
| h3 | 800 | 640 |
| 카드 제목 | 800 | 600 |

대신 자간을 조금 더 좁혀(−0.042em) 덩어리감은 유지합니다. Linear 가 80px 표제에 600 을 쓰고
−3px 자간을 주는 것과 같은 이유입니다 — 큰 글씨는 무게가 아니라 밀도로 무거워 보입니다.


### 누를 수 있는 것은 알약 하나뿐입니다

분류 고르개, "전체 보기", 글의 분류 링크가 **같은 부품**(`global.css` 의 `.pill`)을 씁니다.
전에는 거의 같은 정의가 세 벌 흩어져 있었고, 그래서 화면마다 높이(31/33/40px)와 호버 색이 달랐습니다.

상태는 셋입니다.

| 상태 | 바뀌는 것 |
| :--- | :--- |
| 쉴 때 | 선만 있는 알약 |
| 커서 | **배경만** 밝아짐 (한 가지만) |
| 눌림 | 1px 내려앉음 (`transform` 뿐이라 레이아웃은 그대로) |
| 고른 것 | 앰버로 **평평하게** 채움 — 그라데이션도 글로우도 없음 |

> 빛나는 건 이 사이트에서 전구 하나여야 합니다. 예전 활성 알약은
> `linear-gradient` + `box-shadow` 앰버 글로우였는데, 그러면 화면에 광원이 여럿이 됩니다.

**모서리로 역할을 나눕니다.** 알약(`999px`)은 누르는 것, 각진 라벨(`6px`)은 읽기만 하는 것
(카드 위 분류 칩, 줄 옆 개수). 전부 알약이면 화면이 물렁해 보이고, 무엇을 누를 수 있는지도 흐려집니다.

### 움직이는 시간도 토큰입니다

하나를 모든 곳에 복사하면 가까이 움직이는 것은 굼뜨고 멀리 움직이는 것은 튑니다.
거리와 복잡도에 맞춰 넷 중에서 고릅니다.

| 토큰 | 시간 | 쓰는 곳 |
| :--- | ---: | :--- |
| `--t-tap` | 90ms | 눌림 |
| `--t-fast` | 160ms | 색 · 투명도만 바뀔 때 |
| `--t-base` | 260ms | 몇 px 움직이는 것 (카드 들림) |
| `--t-slow` | 420ms | 크게 펼쳐지는 것 (아이콘 줄 이름) |

UI 쪽에 흩어져 있던 지속시간 19종이 이 넷으로 줄었습니다. 남은 둘(`0.85s` 등장 연출,
`1.2s` 큰 카드 그림 확대)은 움직이는 거리가 커서 일부러 남긴 것입니다.
인트로와 게임 덱의 시간값은 픽셀아트 연출에 맞춰 따로 잰 것이라 건드리지 않습니다.

### 걷어낸 것들 (AI 가 만든 티)

- **호버 하나에 네 가지가 동시에 바뀌던 것** — 색 + 배경 + 테두리 + 들림 + 그림자.
  이제 카드는 "선이 밝아지고 3px 들림", 알약은 "배경만", 아이콘 줄은 "색과 배경".
- **쉬는 동안 그림을 흐려 두기** (`filter: saturate(.92) brightness(.92)`) — 픽셀아트는 도트마다
  색을 골라 찍은 그림입니다. 채도를 깎아 두고 호버에서 되돌리는 건 이유 없는 연출입니다.
- **작은 칩의 `backdrop-filter`** — 20px짜리 칩 뒤를 흐려도 보이지 않습니다. 비용만 듭니다.
- **화살표를 감싸던 동그란 테두리** — 아이콘 하나면 충분합니다.
- **한글에 씌운 모노 대문자 + 넓은 자간** (`BY 심야 작업실`). 라틴 글자의 버릇입니다.
  이름은 본문 글꼴로, 모노는 날짜·개수처럼 자릿수가 중요한 것에만 씁니다.
- **쓰지 않는 디자인 시스템 찌꺼기** — `.btn` · `.btn-lamp` · `.btn-ghost` · `.card` · `.tag` ·
  `.kicker` · `.link-line` · `.wrap`. 화면에서 지워진 뒤로 아무도 쓰지 않는데 CSS 에만 남아 있었습니다.
- **제목 단계 건너뛰기** — 줄별 페이지는 `h1` 다음에 카드가 `h3` 였습니다. 카드 제목은
  줄 안에서는 `h3`, 카드만 있는 페이지에서는 `h2` 가 되도록 `level` 을 받습니다.


## 블로그 (`/blog`)

레퍼런스는 **OpenSea 블로그**입니다 (Mobbin 섹션 링크로 받았습니다). 가져온 건 셋입니다.

1. 맨 앞에 그림이 꽉 찬 **큰 카드 한 장** — 가운데 모인 제목과 이름
2. 카드는 그림 / 제목 / 두어 줄 / 날짜, 이 넷만
3. 분류를 고르는 알약 묶음

다만 **쌓는 방향은 바꿨습니다.** 레퍼런스는 줄을 세로로 쌓지만, 이 사이트는 홈이 이미
"한 화면 + 좌우"라서 블로그도 같은 규칙을 씁니다 (아래 참고).

흰 종이 위의 레퍼런스를 그대로 옮기면 사이트가 갈라지므로, 판만 이 사이트의 어두운 카드
(`--surface` → `#0D0D13` 그라데이션 + `--border`)로 바꿔 깔았습니다. 호버에서 살아나는 건
전등색(`--lamp`) 하나뿐입니다.

### 줄은 셋입니다

| 값 | 이름 | 들어가는 글 |
| :--- | :--- | :--- |
| `devlog` | 작업 기록 | 무엇을 만들었고 왜 그렇게 만들었는지 |
| `craft` | 만드는 법 | 화면 하나 만들자고 판 구덩이들 |
| `notes` | 딴생각 | 작업 사이에 흘린 메모 |

이름과 설명은 `src/lib/blog.ts` 한 곳에 있습니다. 줄을 늘리려면 `CATEGORIES`와
`CATEGORY_ORDER`에 넣고, `content.config.ts`의 `z.enum`과 CMS 설정의 select 옵션을 맞추면 됩니다.
`/blog/c/<줄>/` 페이지는 `CATEGORY_ORDER`를 보고 자동으로 생깁니다.

### 글 하나에 들어가는 항목

```yaml
category: 'craft'                        # 어느 줄에 설지
cover: '/art/blog/neon-cross.png'        # 카드와 글 머리에 깔리는 그림 (400x248)
featured: true                           # 맨 위 큰 카드로 (여러 개면 가장 최근 것)
```

표지는 게임 키아트와 같은 규격입니다 — **400×248 픽셀아트, `image-rendering: pixelated`.**
카드에서는 `object-fit: cover`로 잘리므로 가운데에 중요한 게 오게 그립니다.
전부 PixelLab MCP로 이 사이트를 위해 새로 뽑았습니다.

큰 카드로 선 글은 선반 뒤쪽에 한 번 더 나오지 않습니다.

### 모든 화면이 한 화면입니다 (세로 스크롤 없음)

홈만 그랬던 규칙을 블로그 · 글 · 소개까지 넓혔습니다. **세로로 흐르지 않습니다.**
한 화면에 안 들어가면 아래가 아니라 **오른쪽으로** 이어집니다.

| 화면 | 방식 |
| :--- | :--- |
| 홈 | 게임 덱 (카드 한 장씩 넘기기) |
| 블로그 · 줄별 | **선반** — 카드가 옆으로 늘어선다 (`PostShelf.astro`) |
| 글 | **칸(column)** — 본문이 화면 높이로 잘려 오른쪽으로 이어진다 |
| 소개 | 같은 칸 방식. 내용이 짧아 넓은 화면에서는 두 칸에 다 들어간다 |

글과 소개는 CSS 다단을 씁니다. 핵심은 세 줄입니다.

```css
.reader {
	height: 100%;        /* 높이가 정해져야 */
	column-width: 30rem;
	column-fill: auto;   /* 칸을 아래가 아니라 오른쪽으로 잇는다 */
	overflow-x: auto;
}
```

`column-fill: auto` 가 없으면 브라우저가 칸 높이를 고르게 맞추려 들어서 가로로 넘치지 않습니다.
표·코드블록·표지에는 `break-inside: avoid`, 소제목에는 `break-after: avoid` 를 걸어
칸 경계에서 쪼개지지 않게 했습니다.

> **격자 칸의 `min-width: auto` 를 풀어야 합니다.** `.main` 이 격자라서, 그 안의 가로 스크롤
> 영역이 칸을 밀어내며 화면 밖까지 자랍니다 (폭이 1120px 이어야 할 자리에 2609px 이 나왔습니다).
> `min-width: 0` 을 주면 그제야 칸 안에서 스크롤됩니다.

> **세로 휠을 가로로 돌려 줍니다** (`scripts/hscroll.js`). 마우스에는 가로 휠이 없습니다.
> 트랙패드의 가로 스크롤(`deltaX`)은 건드리지 않고, 양 끝에 닿으면 가장자리 그라데이션을 끕니다.

> **너무 낮은 화면(560px 이하)에서는 원래대로 아래로 흐릅니다.** 칸 높이가 300px도 안 되면
> 한 칸에 두 문단밖에 안 들어가서 넘기는 일만 늘어납니다.

### 탭을 옮겨도 마크와 아이콘 줄은 그대로입니다

페이지마다 전체를 새로 받으면 **위의 마크와 아래 아이콘 줄이 매번 다시 그려집니다.** 같은 자리에
같은 모양으로 다시 나타나긴 하지만, 그 순간 한 번 깜빡이고 등장 연출도 다시 돕니다.

그래서 `<ClientRouter />`(Astro View Transitions)를 켜고, 두 부품에 이름표를 달았습니다.

```astro
<a class="brand tap" data-astro-transition-persist="brand"> …마크… </a>
<footer class="rail" transition:persist="rail"> …아이콘 줄… </footer>
```

이제 페이지를 옮기면 **가운데 내용만 갈립니다.** 마크와 아이콘 줄은 같은 DOM 노드가 그대로 남습니다
(런타임에 붙인 속성까지 그대로 살아남는 것으로 확인했습니다).

> **지시자는 컴포넌트가 아니라 진짜 요소에 붙여야 합니다.** 처음엔 `<Brand transition:persist />` 처럼
> 컴포넌트에 달았는데, 빌드 결과에 `data-astro-transition-persist` 가 아예 없었습니다.

> **같은 이름표가 둘이면 안 됩니다.** 인트로의 노트북 화면 안에도 같은 마크가 들어갑니다.
> 홈에서 이름표가 둘이 되자 Astro 가 **숨어 있는 화면 속 복제본**을 남기고 진짜 마크를 새로 그렸습니다.
> 복제본은 `persist={false}` 로 이름표를 떼야 합니다.

> **인트로는 첫 방문에 한 번입니다.** 페이지를 갈아끼운 뒤에는 `data-intro='off'` 로 못을 박고,
> "인트로 다시 보기" 링크에는 `data-astro-reload` 를 달아 진짜 새로고침을 시킵니다.

또 이 방식이라 **컴포넌트 스크립트는 한 번만 실행됩니다.** 새 화면이 올 때마다 다시 붙여야 합니다.

```js
const boot = () => document.querySelectorAll('[data-deck]').forEach((el) => initDeck(el));
boot();
document.addEventListener('astro:page-load', boot);
```

### 선반은 두 줄입니다

한 줄로 세우면 2560px 화면에서 카드 한 장이 **1156px** 까지 늘어나 그림 아래가 텅 빕니다.
그래서 두 줄로 세우고, 카드는 내용만큼만 높이를 갖습니다 (약 300~340px).

```css
.shelf {
	display: grid;
	grid-auto-flow: column;                        /* 위에서 아래로 채우고 다음 칸으로 */
	grid-template-rows: repeat(2, minmax(0, auto));
	grid-auto-columns: max-content;
	align-content: center;
	overflow-x: auto;
}

.feat.shelf { grid-row: span 2; }                  /* 큰 카드만 두 줄을 한꺼번에 */
```

낮은 화면(높이 640px 이하)에서는 한 줄로 되돌립니다. 두 줄이면 카드가 우표만 해집니다.

> **스크롤 스냅을 걷어냈습니다.** `scroll-snap-type: x` 를 걸어 두면 휠 한 칸(약 100px)이
> 스냅 지점을 못 넘을 때 **제자리로 끌려옵니다.** 2560px 화면에서 휠이 아예 안 듣는 것처럼
> 보였던 원인이 이것이었습니다 — `scrollLeft = 300` 을 넣어도 496 으로 튕겨 나갔습니다.

### 본문 폭은 화면을 따라 넓어집니다

```css
--page: min(1760px, 94vw);   /* 예전에는 1120px 고정 */
```

2560px 화면에서 1120px 고정이면 가운데 절반만 쓰고 양옆이 텅 빕니다. 화면을 따라 넓히되
한 줄이 너무 길어지지 않게 1760px 에서 막았습니다. 2560px 에서 선반이 1680px 이 되어
글 8편이 두 줄에 거의 다 들어옵니다.

### 누르는 것의 글씨는 영문입니다

알약에 한글을 넣으면 폭이 들쭉날쭉하고, 옆의 모노 숫자와 식구가 달라 보입니다.
그래서 알약만 **영문 모노**로 통일했습니다 — `ALL` · `DEVLOG` · `CRAFT` · `NOTES` ·
`ALL POSTS` · `MORE IN CRAFT`. 한글 이름은 `title` 속성으로 남겨 두고, 제목과 본문은 한글 그대로입니다.

### 휠은 화면 어디서 굴려도 됩니다

한 화면짜리 사이트라 스크롤할 곳이 화면에 하나뿐입니다. 커서를 정확히 선반 위에 올려야만 움직이면
답답하므로, 휠은 **창에 한 번 걸고** 그때그때 화면에 있는 가로 스크롤 영역으로 넘깁니다
(`scripts/hscroll.js`). 커서 밑에 따로 스크롤되는 것(코드블록 등)이 있으면 그쪽이 먼저입니다.


### 한글 제목은 단어 중간에서 끊으면 안 됩니다

큰 카드 제목이 "…넘기 / 는 덱으로"처럼 끊겼습니다. 표제는 글씨가 커서 한 번에 눈에 띕니다.

```css
h1, h2, h3, h4 {
	word-break: keep-all;      /* 띄어쓰기에서만 끊는다 */
	overflow-wrap: break-word; /* 그래도 안 들어가는 긴 단어는 예외로 끊는다 */
}
```

`global.css`의 표제 규칙에 넣어 뒀습니다. 같은 이유로 큰 카드 위 라벨은 한글이 아니라
영문(`DEVLOG` · `CRAFT` · `NOTES`)입니다 — 한글에 `letter-spacing: 0.22em`을 주면 글자가 흩어집니다.

## 로고 (`public/brand/`)

사이트 이름 **Matail(맛테일 — '맛있는칵테일')** 의 로고. 상단 마크(`Brand.astro`)·파비콘·미리보기 그림(`og/site.png`)에 씁니다.
리포 · Worker 이름과 주소(`my-site.matail.workers.dev`)는 그대로 `my-site` 입니다 — 바꾸면 배포와 서치 콘솔 확인이 끊깁니다.

마크 하나에 세 가지가 겹칩니다.

- **M** — 양쪽 기둥과 가운데 V
- **마티니 잔** — 가운데 V가 잔, 그 아래 대와 받침
- **전구** — 지금 마크(`Brand.astro`)의 줄과 전구가 그대로 내려와 잔 속 올리브가 됨

선은 끝이 둥근 한 굵기(네온관), 전구만 앰버(`--lamp`). 워드마크는 Studio Marquee 를 아웃라인으로 딴 것이라
폰트 없이도 똑같이 보입니다. 워드마크 대문자 높이는 M 의 높이에 맞췄습니다.

| 파일 | 용도 |
| :--- | :--- |
| `matail-mark.svg` | 어두운 바탕용 마크 (전구 빛 번짐 포함) |
