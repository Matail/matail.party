STREAMS는 숫자 카드 게임이에요. 1~30이 적힌 카드 40장(11~20만 두 장씩)에서 20장이 한 장씩 나오고, 받을 때마다 20칸 중 한 곳에 놓습니다. 한 번 놓으면 못 옮겨요. 왼쪽부터 읽어서 작거나 같은 숫자로 이어지는 구간이 길수록 점수가 커지고, 20칸을 전부 이으면 300점이에요.

같은 카드를 받는 AI와 겨룹니다. AI는 앞으로 나올 카드를 모르고 사람과 같은 정보만 봐요. 사람 플레이를 흉내 내는 모델(human_bc)과 Gumbel AlphaZero로 학습한 정책을 β로 섞어서(piKL) 난이도를 5단계로 나눴어요. 2000판씩 평가하면 평균이 22 / 33 / 39 / 47 / 49점이고, 사람 평균은 31점입니다.

이 글은 9월 29일 밤 웹판을 올린 뒤부터, 30일 밤 Unity판 The STREAMS+를 마지막으로 다시 빌드하기까지의 기록이에요. Unity 리포에는 그동안 PR 9개가 들어갔습니다.

## 첫날 밤: 한 수에 1.2초

웹판을 올리고 두어 보니 한 수 왕복이 1.2초쯤 걸렸어요. 정적 페이지보다 0.6초 느렸습니다. 처음엔 AI 가중치(6.8MB, KV에 있음)를 isolate가 새로 뜰 때마다 다시 받아서 그런 줄 알았어요. KV 읽기에 하루짜리 엣지 캐시를 걸고, `server-timing` 헤더로 구간별 시간을 찍었습니다.

짐작이 틀렸어요. 모델 로드는 0~50ms였고 DB 쓰기가 450ms쯤이었습니다. 한국에서 보낸 요청이 댈러스(DFW)에서 처리되는데 D1 기본 위치는 인천(ICN)이라, 쿼리 하나마다 태평양을 건너고 있었어요.

두 번에 걸쳐 고쳤어요.

1. UPDATE와 INSERT를 batch 하나로 묶어 왕복을 3번에서 2번으로 줄이고, Smart Placement를 켜서 Worker가 D1 가까이에서 돌게 했어요.
2. 그래도 수마다 DB를 두 번 기다리는 건 같았어요. 그래서 게임 상태(덱·보드·턴)를 AES-GCM으로 암호화한 토큰에 담아 클라이언트가 들고 다니게 바꿨습니다. 키는 Worker 비밀값이라 클라이언트는 덱을 읽을 수도, 상태를 고칠 수도 없어요. 응답을 먼저 보내고 D1 기록은 `waitUntil`로 뒤에서 씁니다.

토큰 방식에는 구멍이 하나 생겨요. 옛 토큰을 다시 보내면 같은 턴을 다른 칸에 둘 수 있습니다. 이건 막지 않고 기록하기로 했어요. 같은 턴이 다시 오면 처음 기록은 그대로 두고 `attempts`만 올리고, 분석할 때 `attempts > 1`인 판을 뺍니다.

## 계획: 서버는 그대로, 화면만 새로

같은 날 밤에 Unity로 다시 만드는 계획을 썼어요. 목표는 Unity 클라이언트, 데이터 수집과 실시간 웹 반영, 나중의 멀티플레이였고 0단계부터 5단계까지 나눴습니다.

가장 먼저 정한 건 서버 권위 구조를 그대로 두는 거였어요. 덱과 AI가 서버에만 있으니 Unity는 화면과 입력만 새로 만들면 되고, 가중치가 밖으로 새지 않고, 기록도 한 경로로 모입니다. WebGL을 먼저 만들기로 했고, Unity 프로젝트는 사이트 리포에 넣지 않고 리포를 따로 팠어요. Library 폴더와 에셋이 크고 빌드 흐름도 달라서요. 사이트로는 빌드 결과만 가져옵니다.

화면과 서버 사이에는 `IGameSession` 인터페이스 하나를 뒀어요. UI는 "카드가 왔다 / 내가 놓았다 / 상대가 놓았다 / 끝났다" 이벤트만 압니다. 지금은 AI 대전 하나뿐이지만, 나중에 멀티 방이 생겨도 같은 UI가 돌게 하려는 거예요.

## 0단계: 약속부터 못 박기

Unity를 붙이기 전에 서버와 클라이언트 사이 약속을 문서와 테스트로 고정했어요.

- `docs/streams-api.md`: 요청·응답 JSON, 오류 처리, 토큰 규칙.
- `x-streams-client` 헤더: 웹은 `web/1`, Unity는 `unity-webgl/0.1.0`을 보내고 서버가 `streams_games.client`에 남겨요. 에디터에서 둔 판은 `unity-editor/…`로 남아서 분석에서 빠집니다.
- 규칙 정답지: 서버의 `game.ts`로 보드와 점수 쌍 609개를 뽑아 `rules.json`에 저장했어요.

C#으로 옮긴 규칙은 이 609개와 전부 맞아야 해요. Unity EditMode 테스트로도 확인하지만, GitHub Actions에는 Unity 라이선스가 없어서 `Tools/CoreCheck`라는 .NET 8 콘솔을 따로 만들었어요. 규칙 코드(`Streams.Core`)는 UnityEngine을 참조하지 않으니 Unity 없이 그대로 컴파일됩니다. 푸시할 때마다 돌아요.

> 화면에 쓰는 점수는 항상 서버 값이에요. C# 쪽 계산은 놓기 전에 점수가 어떻게 바뀌는지 보여 주는 미리보기용입니다. 그래도 둘이 어긋나면 미리보기가 틀린 숫자를 보여 주니까 정답지로 묶어 뒀어요.

## 1단계: 씬 없는 Unity

첫 뼈대는 씬도 프리팹도 없이 시작했어요. `GameBootstrap`이 UGUI 화면을 전부 코드로 만듭니다. 난이도 선택부터 20턴, 결과 화면까지 돌았고, 빌드는 메뉴 하나(STREAMS → Build WebGL)로 묶었어요.

그다음에 테이블을 그렸습니다. 1920×1080 탑뷰로 왼쪽에 점수·캐릭터·모드, 가운데에 AI 보드와 내 보드(각각 1×20)와 이번 카드, 오른쪽에 턴·덱·남은 카드·내 구간·점수표를 놨어요. 창 비율이 어떻든 겹치지 않게 스케일은 Expand로 맞췄고요.

그림은 배경·카드·패널·캐릭터를 PixelLab으로 뽑았어요. `PixelArtImporter`가 `Resources/Art` 아래 그림을 점 필터·무압축으로 들여와서 도트가 뭉개지지 않습니다. 글꼴은 영문·숫자에 StreamsPixel, 한글에 Galmuri11(OFL)을 쓰고, Galmuri11은 쓰는 글자만 남긴 서브셋으로 넣었어요.

튜토리얼은 웹 원작 `game.html`에 있던 걸 옮겼어요. 서버 없이 고정 덱으로 한 판을 둡니다. 처음 세 단계는 화면을 어둡게 하고 설명할 부분만 밝히는 온보딩이고, 그 뒤엔 상황에 맞춰 코칭 말풍선이 떠요. 코칭은 네 가지예요. 첫 카드는 가운데쯤에 두라는 것, 초반엔 빈칸을 남기라는 것, 같은 숫자를 다시 받아도 흐름이 이어진다는 것, 그리고 놓을 칸이 왼쪽보다 크고 오른쪽보다 작아야 한다는 것.

효과음은 파일 없이 코드로 합성했어요. 사각파 음을 이어 붙이고, 음마다 끝으로 갈수록 소리를 줄여서 딸깍거림을 없앴습니다.

```csharp
float square = Mathf.Sign(Mathf.Sin(2 * Mathf.PI * hz[n] * t));
data[n * per + i] = square * 0.25f * (1f - (float)i / per);
```

내가 놓으면 880Hz, AI가 두면 587Hz가 짧게 울려요. 이기면 523Hz부터 1047Hz까지 도-미-솔-도로 올라가고, 지면 392→330→262Hz로 내려갑니다.

### WebGL 49.6MiB를 23.9MiB로

Cloudflare Workers 정적 파일은 한 파일에 25MiB까지예요. 줄이기 전 빌드는 합계 49.6MiB였고, wasm 하나가 39.9MiB라 혼자서 한도를 넘었습니다.

두 가지를 바꿨어요. Unity 프로젝트를 처음 열 때 템플릿이 광고·결제 같은 패키지를 깔아 두는데, 쓰지 않는 그 패키지들을 뺐어요. 그리고 코드 최적화를 크기 우선 + LTO로 돌렸습니다. 합계 23.9MiB, wasm 18.3MiB가 됐어요.

압축은 껐어요. Unity의 Brotli 빌드를 쓰려면 서버가 `Content-Encoding: br`을 붙여 줘야 하는데, 끄고 Cloudflare가 전송할 때 압축하게 두는 쪽이 간단했어요. 파일명에는 해시를 붙이고, 빌드 메뉴가 25MiB를 넘는 파일을 찾으면 경고하게 했습니다.

이 빌드를 사이트의 `/games/streams-unity/`에 올리고 홈의 게임 카드를 The STREAMS+로 바꿨어요. 예전 HTML판 `/games/streams/`는 지우지 않고 남겨 뒀습니다.

## 게임 바깥 화면

Unity WebGL 기본 페이지에는 Unity 로고와 푸터가 붙어 있어요. 사이트 안에 두니 혼자 다른 사이트 같아서 WebGL 템플릿을 따로 만들었어요. 사이트 바탕처럼 전등 하나가 켜진 방(원뿔 빛, 바닥빛, 비네트, 그레인)을 깔고, 값은 사이트 `global.css`와 같게 맞췄습니다. 게임 화면은 창에 맞는 16:9에 덱 카드와 같은 청록 테두리 빛을 두르고, 로딩 바는 앰버색으로 했어요. 휴대폰에선 창 전체를 게임에 줍니다.

홈 카드 그림은 두 번 만들었어요. 처음엔 2에서 9로 오르는 네온 카드 계단이었고, 몇 시간 뒤 게임 에셋으로 다시 조합했어요. 청록 펠트 테이블 위에 크림색 카드(1~10 파랑, 11~20 검정, 21~30 빨강)가 한 장씩 놓여서 4→7→9→12→15→18→20→26 오름차순이 되는 9프레임입니다. 카드에서 보는 그림이 게임 화면과 같아졌어요.

## 배경음악과 볼륨

배경음악은 Suno로 만들었어요. 사각파 멜로디 하나, 삼각파 베이스, 가벼운 킥으로 된 110BPM 칩튠이고 1분 10초, 1.7MB예요. `Sound.cs`가 `Resources/Audio/bgm`이 있으면 반복 재생하게 미리 짜여 있어서 파일만 넣으면 됐습니다.

음악이 생기니 끄는 버튼이 필요했어요. 왼쪽 패널 아래에 ON/OFF 버튼과 볼륨 막대를 두고, `AudioListener.volume` 하나로 음악과 효과음을 같이 조절해요. 값은 `PlayerPrefs`에 저장해서 브라우저마다 기억하고, 기본 볼륨은 0.8입니다. 난이도 창이나 튜토리얼 말풍선이 화면을 덮고 있어도 만질 수 있게 그보다 위층에 그렸어요.

## 2단계: 턴으로는 못 담는 것

서버는 이미 판마다 난이도를, 턴마다 카드·칸·생각 시간을 기록하고 있었어요. 사람 모방 모델을 학습시키는 데는 이 기록이 중심이라 그대로 두고, 턴 기록에 안 남는 행동을 따로 모으기로 했습니다.

| 이벤트 | 언제 |
| :--- | :--- |
| `session_start` | 게임을 켤 때 |
| `hover` | 빈칸 위에 0.1초 넘게 머물다가 놓지 않고 떠날 때 (턴·칸·카드·머문 시간) |
| `abandon` | 끝나지 않은 AI 대전을 두고 새 판이나 튜토리얼을 시작할 때 |
| `rematch` | 한 판 더 |

`hover`는 망설임을 재려고 넣었어요. 튜토리얼 판은 기록하지 않습니다.

Unity는 이벤트를 모아 5초마다 최대 50개씩 `POST /api/streams/events`로 보내요. 보내기에 실패하면 다시 보내지 않고 버립니다. **잃어도 되는 기록과 잃으면 안 되는 기록은 섞지 않았어요.** 턴은 `streams_turns`, 이벤트는 `streams_events`로 테이블이 다릅니다. 서버는 묶음 중 틀린 이벤트만 골라 버리고 나머지는 받아요. 플레이어는 익명 `player_id`로만 구분하고, 난이도 창에 무엇을 모으는지 안내 문구를 넣었습니다.

학습에 넣을 판을 고르는 규칙은 D1 뷰 두 개로 만들었어요. `streams_clean_games`는 끝난 AI 대전 중 20턴이 다 있고, 에디터·로컬 테스트가 아니고, `attempts > 1`인 턴이 없는 판이에요. `streams_clean_turns`는 그 판들의 턴인데, 생각 시간이 10분을 넘거나 기록이 없는 턴은 빼지 않고 `slow_turn`으로 표시만 해 둡니다. 내보내기와 분석은 원본 테이블 대신 이 뷰를 읽어요. 규칙마다 한 판씩, 8판을 로컬 D1에 넣어 확인했습니다.

## 3단계: 실시간 통계

모인 기록을 사이트에 실시간으로 보여 주는 일은 Durable Object `StatsHub` 하나가 맡아요. `/start`, 첫 `/move`, 마지막 `/move` 때 집계를 갱신하고, 붙어 있는 웹소켓에 초당 최대 한 번 방송합니다. D1에서 숫자를 세는 건 DO가 처음 뜰 때 한 번뿐이라, 통계 페이지를 보는 사람이 많아도 D1은 그 트래픽을 받지 않아요. 웹소켓 하이버네이션 API를 써서 보는 사람이 가만히 있으면 DO가 잠들고, 웹소켓이 안 되는 곳에서는 5초 캐시가 걸린 스냅숏 API를 5초마다 받아 갑니다.

페이지에는 판 흐름(퍼널), 점수 분포, 난이도별 사람 vs AI, 승무패, 첫 카드 히트맵을 올렸어요. 첫 카드 히트맵은 사람들이 첫 카드를 몇 번 칸에 두는지 보여 줍니다.

> 웹소켓 업그레이드 응답(101)에 CORS 헤더를 붙였다가 500이 났어요. 101 응답은 헤더를 바꿀 수 없습니다. 101에는 CORS 헤더를 붙이지 않게 고쳤어요.

처음엔 최근 판 목록과 클라이언트 비율도 공개 페이지에 넣었는데, 20분도 안 돼서 나눴어요. 공개 쪽엔 합계와 분포만 남기고, 빠진 항목은 `StatsHub`가 아예 모으지 않게 했습니다. 판 하나하나, 클라이언트별 승률, 행동 기록, 생각 시간 분포, 품질 규칙으로 빠진 판은 관리자 전용 Worker `streams-admin`이 D1을 읽어 보여 줘요. 이 Worker는 Cloudflare Access로 막고, Worker 안에서도 `Cf-Access-Jwt-Assertion`의 서명·aud·iss·만료를 직접 확인합니다. 설정이 비어 있으면 모든 요청에 403을 돌려줘서 닫힌 채로 시작해요. 로컬 RSA 키로 서명한 토큰 10가지 경우로 테스트했어요.

통계는 처음에 게임 페이지 오른쪽 위 링크로 들어가게 했어요. 한 시간이 안 돼서 사이트 아래 메뉴에 통계 탭(`/stats/`)을 따로 만들고 그 링크는 지웠습니다. 게임이 늘어도 통계를 한곳에서 보려고요.

## 마무리: 검색 노출과 스플래시

게임 페이지는 캔버스 하나라 검색 엔진이 읽을 글자가 없어요. 설명, 미리보기 이미지(1200×630), `VideoGame` 구조화 정보를 넣고, 화면에는 안 보이지만 검색 엔진과 스크린리더가 읽는 소개 문단을 따로 뒀어요. 예전 HTML판과 관리 화면은 noindex로 뺐습니다.

마지막으로 시작할 때 뜨는 Unity 로고를 껐어요. Unity 6부터는 Personal 라이선스도 스플래시를 끌 수 있습니다. ProjectSettings와 빌드 설정 메뉴 양쪽에서 끄고 다시 빌드하니 바뀐 건 data 파일 하나였어요. loader·framework·wasm은 해시가 그대로라, 사이트 쪽에선 data 파일 이름 한 줄만 고쳤습니다.

## 남은 것

계획의 4단계는 모델 버전 관리예요. 지금 AI 버전은 코드에 상수(`v17-pikl`)로 박혀 있어요. KV에 가중치를 버전별로 올리고 `active.json`이 난이도별로 쓸 버전을 가리키게 바꾸면, 새 모델을 일부 판에만 내보내서 실제 사람 상대 승률로 비교할 수 있습니다.

5단계는 멀티플레이예요. 모두 같은 카드를 동시에 받는 게임이라 프레임 동기화는 필요 없고, 방 하나를 DO 하나로 둘 생각이에요. Unity 쪽은 `IGameSession`을 구현하는 `RoomSession`을 더하면 지금 화면을 그대로 쓸 수 있습니다. 최대 인원, 빈자리를 AI로 채울지, 턴 제한 시간은 아직 정하지 못했어요.
